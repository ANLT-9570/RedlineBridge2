# 文档对比器 V1 设计

## 1. 目标

构建一个**桌面优先、纯本地运行**的文档对比器，第一版只支持以下两类对比：

- `.docx` ↔ `.docx`
- 文本型 `PDF` ↔ 文本型 `PDF`

产品的核心体验不是普通文本 diff，而是：

**尽量还原原文排版，并在原文字位置通过颜色显示新增、删除、修改。**

第一版优先级排序：
1. 结果准确
2. 接近原文的阅读体验
3. 操作简单
4. 处理速度

## 2. 非目标

第一版明确不做以下内容：

- `.doc` 支持
- 扫描版 PDF / OCR
- `Word ↔ PDF` 跨格式对比
- 云端处理
- 导出对比报告
- 账号、协作、云同步
- 完整文档编辑能力
- 图片内容识别、手写、签章、批注语义对比
- SmartArt、复杂浮动对象、嵌入图表内部语义对比

网页端是后续方向，但**不是 V1 交付目标**。

## 3. 目标用户与核心任务

目标用户是需要审阅办公文档差异的通用办公用户。

V1 要稳定支持的核心任务是：

1. 在本地选择两份同格式文档
2. 打开对比结果页
3. 在接近原文的双栏阅读视图中快速定位差异
4. 通过颜色和跳转能力判断哪里发生了新增、删除、修改

## 4. 支持范围

### 4.1 输入

- 左侧文档：旧版本
- 右侧文档：新版本
- 支持本地文件选择
- 支持格式：`.docx`、文本型 `PDF`

### 4.2 输出

- 双栏原文对比视图
- 差异颜色标注
- 差异侧栏
- 上一处 / 下一处差异导航
- 页面和位置跳转

### 4.3 差异类型

V1 识别三类差异：

- **新增**：仅在新文档中出现的内容
- **删除**：仅在旧文档中出现的内容
- **修改**：同一位置上的局部改动，尽量识别为一次修改，而不是拆成大量删除 + 新增

## 5. 产品交互设计

### 5.1 首页

首页包含：

- 左文档选择区
- 右文档选择区
- 支持格式说明
- “开始对比”按钮

如果两个文件格式不同，V1 直接阻止进入对比流程，并提示当前版本仅支持同格式对比。

### 5.2 对比页布局

对比页分为 3 个区域：

1. **左侧文档区**：显示旧文档
2. **右侧文档区**：显示新文档
3. **差异侧栏**：显示差异列表、摘要与跳转入口

顶部工具栏包含：

- 上一处差异
- 下一处差异
- 差异总数
- 显示 / 隐藏差异侧栏
- 重新选择文件

### 5.3 浏览原则

- 默认采用**双栏原文视图**
- 左侧固定表示旧文档，右侧固定表示新文档
- 导航以“差异跳转”为主，不强依赖同步滚动
- 点击某一条差异时，左右两侧都应尽量跳到对应位置
- 不要求两侧全文滚动始终严格同步，因为分页与长度可能不同

### 5.4 颜色约定

V1 固定颜色，不提供自定义：

- 新增：绿色
- 删除：红色
- 修改：蓝色或橙色
- 删除占位标记：红色标识

## 6. 渲染与展示要求

### 6.1 Word ↔ Word

Word 路径的目标是**尽量接近 Microsoft Word 中的版式表现**。

渲染要求：

- 保留分页感
- 尽量还原段落、字体、行距、缩进、表格等基础版式
- 差异必须叠加在原文字位置上，而不是把文档改造成纯文本 diff 结果

展示要求：

- 原文仍然可读
- 有差异的文字通过颜色强调
- 不因为标注差异而破坏整体阅读结构

### 6.2 PDF ↔ PDF

PDF 路径直接基于**原 PDF 页面**进行展示。

渲染要求：

- 不重新排版 PDF
- 保持 PDF 原始页面视觉结构
- 在原文字位置叠加差异颜色层

### 6.3 删除占位标记

删除内容不应为了展示差异而把完整旧内容强行插回到另一侧页面里，避免破坏版面。

V1 采用以下原则：

- 旧文档侧保留原始已删除内容，并用删除色标识
- 新文档侧在对应锚点位置显示简洁的删除占位标记
- 新增内容反向处理：新文档侧显示新增文字，旧文档侧在必要时显示对应占位提示

### 6.4 表格文本

V1 需要覆盖表格中的文本差异。

要求：

- 表格整体位置尽量保持原状
- 单元格文字可以参与差异识别和着色
- 不要求 V1 处理复杂表格语义重建，只要求文本差异可见且不明显破坏阅读

## 7. 差异计算模型

虽然前台强调原版式展示，后台仍然需要统一 diff 逻辑。

### 7.1 抽取内容单元

对两类文档都要提取以下信息：

- 文本内容
- 文本顺序
- 所属块 / 段落 / 行 / 页信息
- 页面内大致位置

### 7.2 匹配策略

V1 采用分层匹配：

1. 先做块级匹配，定位大体对应区域
2. 再在匹配块内部做更细粒度差异识别
3. 小范围改动优先识别为“修改”
4. 只有无法合理归并时，才拆成“删除 + 新增”

### 7.3 映射策略

差异识别完成后，必须把结果映射回各自渲染层：

- Word 结果映射回 Word 页面中的文字位置
- PDF 结果映射回 PDF 页面中的文字位置

目标不是生成一份新的“对比文档”，而是在两份原文视图上叠加差异信息。

## 8. 错误处理与可信度边界

### 8.1 必须显式报错的情况

以下情况必须明确提示用户，不能静默给出不可靠结果：

- 文件格式不支持
- 两个文件格式不一致
- PDF 无法提取文字（疑似扫描版）
- 文件损坏、加密或解析失败
- 某些对象导致渲染失败

### 8.2 准确性原则

准确性优先于“尽量什么都标出来”。

具体原则：

- 无法可靠对齐时，不要强行认定为修改
- 宁可少报，也不要大面积误报
- 如果系统对某处匹配把握不足，可以在界面上提示该差异可信度较低

### 8.3 本地处理承诺

V1 默认纯本地处理：

- 不上传原文件
- 不依赖云端解析服务
- 不需要用户登录
- 对比结果默认只存在本地当前使用环境中

## 9. 架构约束

V1 虽然只做桌面端，但技术设计不应阻塞未来扩展网页端。

因此架构上应拆分为以下角色：

1. **桌面应用壳层**
   - 负责窗口、文件选择、页面导航、结果展示

2. **文档渲染层**
   - Word 高保真渲染能力
   - PDF 原页面渲染能力

3. **差异计算层**
   - 文本抽取
   - 块级 / 细粒度匹配
   - 差异分类

4. **映射与标注层**
   - 将差异结果映射回页面坐标与文字对象
   - 驱动颜色覆盖与占位标记展示

要求：

- 差异计算层尽量与 UI 解耦
- 文档渲染层与差异计算层通过明确数据结构交互
- 不为了未来网页端而牺牲 V1 的本地高保真目标

## 10. MVP 验收标准

V1 达标的标准不是功能多，而是下面这些事情能稳定成立：

1. 用户可以在本地选择两份 `.docx` 或两份文本型 `PDF`
2. 系统可以进入双栏对比页并展示接近原文的版式
3. 新增、删除、修改可以在原文字位置通过颜色看出来
4. 删除不会通过粗暴插回整段文字来破坏版面，而是使用占位策略
5. 用户可以通过差异侧栏和上一处 / 下一处快速跳转
6. 不支持的输入和失败情况会被明确提示
7. 整个流程默认不上传用户文件

## 11. 测试与验证要求

### 11.1 功能验证

至少需要覆盖以下样例：

- Word：纯正文新增 / 删除 / 修改
- Word：表格文本变化
- Word：分页附近的差异
- PDF：纯正文新增 / 删除 / 修改
- PDF：多页 PDF 的差异定位
- 两份文件完全相同
- 文件格式不一致
- 扫描版 PDF / 无文本层 PDF

### 11.2 展示验证

需要人工验收以下问题：

- 双栏视图是否仍然像在读原文
- 差异颜色是否清晰但不过度破坏可读性
- 删除占位标记是否足够明显且不过分干扰版面
- 点击差异跳转后，两侧是否能到达合理位置

### 11.3 本地处理验证

需要验证：

- 对比流程在离线环境中仍可运行
- 默认路径下不会把文档上传到远端服务

## 12. 结论

V1 是一个**同格式文档高保真对比查看器**，而不是通用文本 diff 工具，也不是完整文档编辑器。

其成败关键在于：

- Word 页面还原是否足够接近原文
- PDF 页面标注是否足够稳定
- 差异识别是否准确且不碎
- 导航是否让用户快速找到改动

如果以上四点成立，这个产品即使功能范围克制，也已经具备明确价值。
